# Phase 8B — remaining issues and practical limits

- **Human understanding and fun remain unmeasured.** Native interaction, screenshots and synchronized processes support technical playability. They do not establish that newcomers understand the first destination, enjoy every job, find the ambiguity satisfying or want another day. Use the four-person protocol in the playtest guide before expanding scope.
- **Multiplayer evidence is localhost technical evidence.** Separate processes exercise host/join and reconnection. Cross-machine LAN, packet loss, high latency and a real conversation between four people remain untested.
- **This is one suspicious day.** There is one bounded covert track, three personal-note templates and a small set of route/correction choices. It is a foundation for overlapping work, not the full multi-day deduction game or proof of replayability. Repeated objectives will need variation after human tests.
- **No durable match resume or host migration.** A live application's reconnect token preserves its private progress under a new client id. Closing that app loses the token; losing the host ends the session. Tokens are continuity aids, not authenticated player identities.
- **Observation scoping is intentionally small.** Clients get nearby observable item custody; ordinary shared progress and declared operational notes remain public. The authoritative host retains truth. There is no anti-cheat, witness memory, complete evidence notebook or inferred guilt.
- **Presentation still has prototype edges.** Existing market entry uses an offset interior and a portal threshold, not a seamless streaming building. The environment includes decorative closed homes. New cabinet doors are static open meshes; the kiosk is a noticeboard/writing station, not an NPC office. The ambient chord loop is basic and needs a real musical pass. Existing town fixtures still vary in fidelity.
- **Editor/tool access limits.** Unity MCP was absent, Blender MCP disconnected and Figma MCP hit its Starter quota. CLI-built native output and editable Unity/Blender sources are supplied; no live Figma file or editor-MCP review is claimed.
- **Build/engine warnings remain.** Unity's inherited pipeline generated warnings during a successful build. Some native shutdown logs show allocator/graphics-resource warnings. The validation report distinguishes these from play-time exceptions; a release-build cleanup and longer soak are still needed.
- **Homes, cozy interiors, poker/cards, darts, arcades and the economy are roadmap items.** They are documented future phases. No paid or earned deduction advantage is implemented.

These limits are recorded so the next pass can target demonstrated player problems rather than treating successful automation as a finished game.
